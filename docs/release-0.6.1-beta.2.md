# MCP Toolkit 0.6.1-beta.2 — AutoCAD 通訊與原視窗恢復修正

本版為未簽章 Beta 測試版。Windows Smart App Control／SmartScreen 可能阻擋安裝或載入；本版不宣稱通過 SAC 相容性驗收，也不要求關閉 Windows 保護。後續版本仍維持既有簽章發布門檻。

## 如何更新

先儲存並關閉已安裝 MCP 對應的 CAD 軟體，在 Toolkit「設定與更新」啟用「接收 Beta 測試版更新」，按「檢查更新」及「立即更新」。更新沿用安裝位置並保留設定；重新啟動 Codex，讓 MCP 重新載入。這次原生外掛也需要成套更新，不能只更換 Toolkit EXE。

手動更新請將 `McpToolkitSetup.exe` 與 `cad-toolkit-payload.zip` 放在同一資料夾後執行。只下載 EXE 且無法連網取得 payload，不能完成安裝。

「不用關閉 AutoCAD」是指安裝新版後的中斷恢復流程；一般軟體更新仍需先儲存並關閉 CAD，不會自動關閉使用者的工作。

## 本次修正

- **不用關閉 AutoCAD 就能恢復連線**：在中斷恢復面板按「檢查並恢復連線」，由原生外掛確認視窗、文件與忙碌狀態，持續撤銷舊要求並隔離舊指令。檢查通過後，使用者檢查圖面、勾選確認，才解除修改暫停。
- **舊指令不會自動重送**：準備恢復不會執行舊要求；確認後才接受明確的新操作。遲到的舊通知或相同 request ID 仍被外掛拒絕。解除暫停不代表上一批成功，也不會復原已產生的修改。
- **唯讀與修改分開處理**：修改結果不明時，已審核的查圖操作仍走 Toolkit 管理的獨立唯讀入口。查詢成功不解除修改屏障；查詢逾時不再被當成可能部分改圖。任意 LISP、存檔或物件修改不會因 readOnlyHint 而被視為唯讀。
- **修正通知前失敗的誤判**：AutoCAD 視窗剛開啟時，COM 可能暫時拒絕呼叫。只對通知前的唯讀預檢做短暫等待；確定未送出的失敗不再要求重開。SendCommand 已呼叫後絕不重試，仍按結果不明處理。
- **改善恢復面板**：分別顯示唯讀可用與修改暫停；恢復檢查有進行中提示；原始錯誤收在技術詳細資料。單純「重新檢查」不等於修復連線。
- **換圖後重新檢查**：切換到其他圖面，或切走再切回，都會使原本的恢復確認失效。不能用檔名、端口或前景視窗代替內部識別。

## 保護與限制

CAD 仍在執行或等待輸入、目標不符、存在其他未知要求、舊外掛或無法取得原生隔離證據時，不會強制解除暫停。請先完成／取消目前操作，或儲存並重開作為備援。AutoCAD 仍要求唯一明確的主視窗。

Toolkit 的保護適用於自身管理的通道，不會封鎖第三方程式直接存取 CAD，也不保證任意 LISP 的工作可整批回滾。

## 驗證

- 169 項 Python、32 項一般桌面、10 項既有恢復介面、8 項原視窗恢復介面與 28 項更新／清理測試通過。
- AutoCAD 2026 原生外掛完成 33 項整合檢查，包含中途關閉、逾時、原視窗恢復、遲到通知、永久拒絕舊 request ID 及等待輸入。此套使用隔離的自有 CAD 程序與 WM_CHAR 通知。
- 實際本機透過正式 COM 維護通知及已安裝 MCP stdio 驗證：不換 PID、不換圖面，能準備恢復，唯讀可用、修改仍受阻擋，圖元數及 DBMOD 不變。使用者已確認恢復流程可用。
- LT 2027 的原生入口及非 COM 通知有程式層級覆蓋，尚未完成 LT 2027 實機驗證，不視為已認證。

本次不包含圖塊庫功能，也不改變 Rhino／Inventor 的上游套件版本。
